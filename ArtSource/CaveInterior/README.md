# 山体内部洞道（第二版）

用于 `Assets/Scenes/FildScene.unity`。本版不再给薄墙迷宫加一个大屋顶，而是把可走区域做成连通的洞道：地面、岩壁和拱顶共用一张连续内表面，通道以外是不可进入的岩体。

## 路线与查看方式

保留灰模的南入口、向左拐入、中央分岔、上方回转、东北出口的整体走向，以及三条通往宝箱和入队点的支路。洞道宽窄和转角重新塑形，不承诺保留原先外围的全部空地，也不逐段复制薄墙轮廓。敌人、宝箱、入队点和出生/返回点的数据没有移动。

在 Unity 打开 FildScene 后进入 Play Mode，沿用原来的移动和右键转镜头。`Environment/CaveInterior` 是新环境。镜头碰到岩壁或拱顶会拉近，其他场景的默认相机配置不变。

旧 `VolcanoCaveEnvironment`、试验 `CaveCeiling` 仍在场景内，保持关闭。对象开关不包含旧照明设置；每次生成前会把场景备份到忽略目录 `Library/CaveInterior/Backups/`。

洞穴网格主要面向内部。从场景外上方观察会看到背面，不是供远景观看的山体外壳。

## 编辑入口

- `tunnel-layout.json`：按灰模整理的洞道中心线，每个点的 `x/z` 是平面坐标，`radius` 是近似半宽，`height` 是近似洞顶高度。主路和支路有独立名称。
- `Assets/Editor/VolcanoCave/CaveTunnelGeometry.cs`：平滑中心线、连续内部空间、岩面起伏、分块网格生成。分岔共享空间，不是互相穿插的独立管道。
- `Assets/Editor/VolcanoCave/CaveInteriorBuilder.cs`：生成预制体、灯光、少量垂岩和岩浆细缝，并验证全部交互点。
- `Assets/Art/Environment/CaveInterior/CaveInterior.prefab`、`CaveInteriorMeshes.asset`：生成的 Unity 原生资源，不需要 Blender 才能运行或重建。
- `Cave_Stone.mat` 和 `VolcanoCave/Shaders/CaveInteriorRock.shader`：本洞窟专用岩石表现。地面和侧壁连续，地面颜色由法线方向稍微压暗，不改 Boss 场景的共享材质。第一版的 `Cave_Floor.mat` 留作旧材质参考，本版不再引用。
- `Assets/Scripts/Environment/CaveCameraConstraint.cs`：环境内镜头碰撞，包括近裁剪面空间。
- `Assets/Scripts/Environment/CaveSpawnRecovery.cs`：旧坐标落在新填入的岩体中时，移到最近的可用通道；不读写存档文件，也不改变其他场景。

修改布局后，在编辑模式使用 `Tools > Cave Interior > 1 Build Enclosed Cave`。重建会替换本组生成网格、灯光和材质；长期手工修改应写入布局或生成器，或另存独立资源。旧 Walls 只作为保留的灰模参考，不再自动驱动第二版形状。

生成表面包含环境碰撞和洞内地面。原场景的地面碰撞仍保留，洞内地表在其上方约 0.012 米，连续走行使用新地表。不存在运行时生成网格的开销。敌人的追踪/徘徊系统未改为寻路系统。

## 验证

`Tools > Cave Interior > 2 Verify Route and Camera` 检查出生、返回、5 个敌人、3 个宝箱和入队点的可达性；检查可达区域洞顶覆盖、镜头四档俯仰/十二方向，以及三个旧坐标的安全恢复。

`3 Render Previews` 生成入口、转角、岔路和高角度预览。`Previews/tunnel-map.png` 显示洞道平面，橙点为目标位置。

`4 Run Traversal Smoke Test` 自动进入/退出 Play Mode，用角色实际刚体经过主路和三条支路。敌人的移动与碰撞只在这次临时测试里关闭，不调用存档。它不替代实际战斗、宝箱领取、入队和场景切换的完整回归。

以 `validation.txt` 和 `playtest.txt` 的最新结果为准。预览中仍使用方块占位角色。本轮重点是洞内空间结构和可走性，材质、灯光和局部岩石细节仍可继续调整。

本次实际行走检查通过：132.3 米、280 个路径点，主路和三条支路均经过，保持贴地、镜头在洞内，运行时报错为 0。静态检查覆盖 11 个目标、1160 条洞顶射线和 624 个镜头姿态。`5 Reload and Verify Saved Scene` 可在保存场景后重新打开并重做静态检查，确认保存后的资源引用有效。
