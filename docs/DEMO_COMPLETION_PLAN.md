# Demo Completion Plan / Demo 完成清单与工作记忆

更新日期：2026-10-25。

这是近期讨论的持久记录和后续工作的入口，不是完整需求规格。明确需求、实现建议和待验收项分开记录；后续以用户的新决定为准。不要把“脚本已经存在”当作体验已完成，也不要把旧测试记录未打勾的项目直接当作当前缺失。

## 1. 用户明确表达的方向

- 项目已经持续较久，需要加快完成 Demo；之后用户计划制作另一个小游戏。
- 不能仅凭“系统可以运行”就判断 Demo 只剩测试。仍需梳理内容、表现和功能缺口。
- 存读档需要整合到点击右上角角色头像后进入的系统菜单，而不是只停留在原 ESC 菜单。
- 存读档参考图采用纵向逐条排列的存档列表，并提供保存和读取功能。
- Item、Skill 等目前用 ScriptableObject 配置原本是过渡方案；用户希望主要玩法配置最终由外部表格制作和驱动，不局限于这两类数据。
- 装备系统暂缓；洞窟拓宽暂缓。不要为这次菜单或数据工作顺带重做洞窟和模型。
- 原左侧队伍 HUD 隐藏，只显示新的头像 HUD；头像上的悬停数值和姓名已按用户要求移除，不要顺带恢复。

## 2. 上轮建议，仍可调整

### 存读档菜单

- 沿用当前头像入口和系统菜单，在 Status / Item 之外增加 Save / Load 页。
- 页内切换保存、读取模式，共用存档列表。
- 初版摘要建议包含槽位编号、队伍头像、地点和保存时间；这些具体字段以及槽位数量尚未由用户最终确认。
- 空槽不能读取，覆盖已有存档和读取操作需要确认，并显示成功或失败结果。
- 初版建议暂不制作截图缩略图，不顺带扩展参考图中的音量设置或退出游戏页面。
- 同时检查标题画面的读取入口如何进入同一套槽位选择，避免仍然隐式读取旧的单一文件。

### 配表流程

- ScriptableObject 本身已经是数据驱动；Excel / CSV 接入主要改变数据制作与批量维护方式，不必重写战斗系统。
- 建议流程：外部表格 -> 解析与校验 -> 更新现有 SO -> 现有数据库查询与运行时逻辑。
- 更新应保留现有资源 GUID 和场景引用；不要每次导入都删除并重建 SO。
- 同一数值应有唯一制作来源，避免表格和 Inspector 的修改相互覆盖。
- 批量配置适合接表：道具、技能、角色初始属性、成长/经验、敌群、掉落等。
- Unity 资产引用可通过稳定 ID 绑定；模型、材质、头像、场景和摄像机预设不要求全部搬进表格。
- 当前 HP、背包和剧情进度属于运行时/存档状态，不从静态配置表重新生成。
- 先建立一条最小可验证流程，以 Item / Skill 为首批，再按需求扩展；不一次迁移所有 Data 类。
- 建议顺序为先完成存读档整合，再做最小配表流程。这是实现建议，不是已经确认的固定排期。

## 3. 2026-10-22 只读核对的实现状态

已存在的基础：

- Status / Item 系统菜单、头像 HP/MP HUD、角色属性接口已提交。
- 探索、普通/联合遭遇、入队、宝箱、战斗胜负结算、成长和 JSON 存档已有实现。
- Dialogue / VN、结尾触发、DemoEndPanel 和回标题控制器已有实现。
- Boss_FieldScene 配置了 boss_ending_001 自动事件，以 boss_spawn_001 清除为条件，使用 VN，并在结束后调用 ShowDemoEnd。
- TitleScene、FildScene、BattleScene、Boss_FieldScene 已加入构建场景列表。这不等于独立构建已经验收通过。

确认的功能或技术缺口：

- SaveSystem 目前固定使用 save.json，尚无多槽位和列表摘要接口；Load 的读文件/解析异常保护及安全写入还需补齐。
- 未发现项目自有的 Excel / CSV 导入流程。
- Item、Character、Encounter 已有 ID；SkillData 尚无稳定 skillId。
- Character 的等级成长和经验需求仍在代码中写定。
- Buff 道具只保留字段和占位处理；如果 Demo 不使用 Buff，应避免向玩家呈现可用效果，不必为此补全整套系统。
- 敌方选技能目前按类型、权重和冷却筛选，尚未在该筛选处检查 MP；技能执行后无条件登记冷却。是否影响当前内容需要复现和配置核查，不能只据此宣称 Boss 当前已经卡死。
- BossEnding 仍使用 Placeholder 命名的对白资源，文本与人物立绘需要内容验收。
- 未在项目自有脚本中找到 AudioSource / AudioClip 播放和音量设置实现，也未在已扫描的场景/Prefab 中找到 AudioSource。音频表现暂列为待确认需求，不扩成完整设置系统。

## 8. 2026-10-24：Boss 二阶段

- 用户决定先制作“半血以下二阶段，固定蓄力后释放 AOE”的机制。
- 已为 `boss_001` 配置 50% 阈值和现有 `MagmaBurst`，二阶段固定重复“蓄力、AOE”。
- 转阶段在 Boss 自己的行动中处理，不赠送额外行动，回血不退回一阶段。
- 蓄力和释放各占一次行动，沿用原伤害公式，不增加永久攻击力或额外蓄力伤害。
- 每只敌人的阶段/蓄力状态独立；血条上方保留蓄力提示，死亡或重新初始化时清除。
- 行动顺序头像旁同步保留蓄力提示，以免特写镜头把头顶提示裁出画面。
- Unity Play Mode 63 个断言通过，包含阶段边界、多人群攻、单次扣 MP、MP 不足回退、死亡取消及初始化重置；未修改真实存档或源资源数值。
- 本次数值不做平衡调整；实际速度下的准备机会、Boss 战时长与难度仍需用户试玩。
- 配置和代码说明见 [Boss Phase Two](BOSS_PHASE_TWO.md)。
